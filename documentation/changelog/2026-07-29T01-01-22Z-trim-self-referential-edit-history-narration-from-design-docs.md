# Trim self-referential edit-history narration from design docs

Joakim asked for an "llm-check" pass over documentation/ to effectivize language, cut duplication, and drop unnecessary information — with a specific example: prose that narrates its own correction history ("this function should do X, not Y as previously stated, changed on [date]") instead of just stating the current fact. Ran a calibration set on `photo-server/README.md` first (approved), then went folder-by-folder through the rest of `documentation/` applying the same bar.

Cut this pattern from `photo-server/README.md` (duplicate "fixed since" restatement, stale relative-time markers, doc-authorship history, the flagged example itself, self-referential staleness commentary), `policies/POLICY.md` (a "corrected 2026-07-29"/"earlier research pass mistakenly used" narration duplicated in `income/TODO.md`), `policies/AUTHENTICATION.md` ("raised again this session — resolved by re-surfacing a decision already made", "not by how the list was originally written"), and `gui/README.md` (a removed-feature note already fully covered in its own `TODO.md`). Left `TODO.md`/build-roadmap files, `HARDWARE.md`, `DEPLOYMENT.md`, and `bugs/` entries untouched — those are intentionally chronological logs/runbooks where the dated "why" is operationally load-bearing (e.g. HARDWARE.md's memtest-gate history), not narrative clutter mixed into a current-state description. Confirmed via `tools/redundancy_scan` afterward that no new actionable duplication remains beyond already-documented precedent (templated boilerplate, rule citations in bug reports).
