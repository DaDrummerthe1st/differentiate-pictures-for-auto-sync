# Design number-plate OCR, custom privacy categories, entity-alias merge, cross-household identity linking

Follow-on from the previous tagging/OCR discussion. Joakim asked to add number-plate recognition, aggregate per-category sharing preferences, support custom user-defined privacy categories (blueprint example), and — the hard one — connect two households' independently-tagged names for the same real person ("Jocke" vs "Joakim").

- **Number plate (ANPR)**: added to DETECTORS.md area D as its own row. First pass over-flagged it as a DPIA/legal concern; corrected same session per Joakim — no Swedish law bars a private lookup, and this project builds a capability into the codebase, it isn't the GDPR controller for an independent self-hosting user's own data (same non-liability logic as a camera manufacturer). The real, narrower point that remains: household exemption is the relevant lens for whoever ends up controller of a given instance.
- **Privacy-decision preference aggregate** (ARCHITECTURE.md): Joakim's `"email": "blurred-public:93%..."` shape, designed as a recomputed suggestion signal (same shape as the existing usage-intent score), never an auto-decision. Flagged a real dependency: it assumes named audience circles/scopes that don't exist in the sharing model yet — not silently assumed into existence.
- **Custom privacy categories** (TAXONOMY.md): a user-typed free-text description becomes a zero-shot CLIP prompt — no new model. The "blur for everyone except two people" exception case turns out to already work via the existing any-tag-is-shareable mechanism; no new access-control primitive needed.
- **Entity alias merge** (tags/TODO.md): extended the existing entity-dedup item with a real trigger — name-string similarity won't catch "Jocke"/"Joakim" (no shared substring), embedding similarity will; surfaces a confirm-to-merge prompt, never auto-merges.
- **Cross-household identity linking** (ARCHITECTURE.md): the real answer. For a person with (or who can get) an account, linking both households' local entities to the same `linked_account_user_id` via two separate email-bound invites solves it entirely with already-designed mechanism, no cross-household embedding sharing needed. For an animal or a person who'll never have an account, there's no authenticated party to confirm the match — genuinely still open; researched Private Set Intersection/Privacy-Preserving Record Linkage as the real cryptographic answer to "how is this even theoretically possible," same not-proven-on-target-hardware caveat as the project's existing homomorphic-encryption finding.

GLOSSARY.md gets ANPR, DPIA, zero-shot classification, and PSI/PPRL entries.
