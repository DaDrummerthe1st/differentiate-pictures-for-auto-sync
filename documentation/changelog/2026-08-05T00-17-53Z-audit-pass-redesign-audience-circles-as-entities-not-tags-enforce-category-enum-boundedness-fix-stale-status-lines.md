# Audit pass: redesign audience circles as entities not tags, enforce category-enum boundedness, fix stale Status lines

Joakim asked for an audit of this session's own doc edits: inconsistencies, space savings, and durably lowering token cost for every future session, not just a one-off tidy-up. Also asked whether "Co-presence/group" is now obsolete given audience circles.

- **Audience circles redesigned**: the previous pass modeled a circle as a tag, which would have made it an unenumerated 13th category and didn't fit "a tag is what the system found out about a photo" (Joakim's own framing) — a circle isn't about any photo at all. Moved to `entities.entity_type='circle'` (SCHEMA.md), a fifth instance of the existing owner-scoped-record pattern rather than a new one, with members in `attributes.member_entity_ids` instead of `tag_references`. This structurally guarantees a circle can never contribute to per-photo tag clutter. TAXONOMY.md, ARCHITECTURE.md, SHARING.md, GLOSSARY.md updated to match.
- **Category-enum-boundedness made explicit**: added a clarifying note to TAXONOMY.md that `category` is a closed 12-value enum by design, new detection areas (number plates, custom categories) resolve to existing categories rather than minting new ones, and not every detector fact becomes a tag — the index stores everything, only a curated/confirmed subset surfaces as a tag. Connects to the Curator's existing grounded-narration design: a tag and a future LLM narration are two views of the same underlying facts, not two data models.
- **Number-plate detection** (DETECTORS.md) made to explicitly funnel into the existing `privacy` category via the same OCR confirm-or-blur mechanism, closing a gap where it hadn't been assigned a category at all.
- **Co-presence/group confirmed NOT obsolete**: answers a different question (who's depicted together in one photo, a content fact) than a circle (a reusable sharing list, never photo content) — the earlier naming collision is moot now that they live in different namespaces (tag category vs. entity type), not just avoided by word choice.
- **Stale Status lines fixed** in TAXONOMY.md and ARCHITECTURE.md, which had drifted behind their own bodies' dated inline additions within this same session. Filed and immediately resolved a process-lapse report (`documentation/bugs/claude-bugs/fixed/2026-08-05-status-line-drifts-stale-...md`) and added a durable rule to documentation/README.md's "Keeping docs current" section: a dated inline addition must update that file's own Status section in the same edit, going forward for every session, not just this one.

- **Doc size**: +5,889 chars (net, across README.md, tags/SCHEMA.md, tags/TAXONOMY.md, curation/ARCHITECTURE.md, curation/DETECTORS.md, upload-and-share/SHARING.md, GLOSSARY.md, and the new bug-report file; Unicode codepoints, per DOC_METRICS.md methodology).
