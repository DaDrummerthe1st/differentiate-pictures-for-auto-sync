## Known drift

All paths below are relative to [prototypes/differentiate_pictures/](../../previous-work/multi-user-web-app/prototypes/differentiate_pictures/), where this code now lives — see [README.md](README.md) for why.

- **Database engine mismatch**: `requirements.txt` and `app/database.py` currently target MySQL (`mysql-connector-python`), but the intended engine going forward is **PostgreSQL**. Treat the current MySQL code as a draft, not the target. Migrate when database work resumes — don't build new features on top of the MySQL layer without checking first. (photo-server/ is a fresh stack and made the Postgres choice independently — same conclusion, unrelated codebase.)
- `app/local_mysql.py` (gitignored credentials module) will need renaming/replacing once the Postgres migration happens.
- **Unverified dependency bump (2026-07-15)**: `requirements.txt` was pinned to the latest CVE-checked versions of everything it lists (numpy 2.5.1, opencv-python 5.0.0.93, Pillow 12.3.0, exif 1.6.1, python-magic 0.4.27, mysql-connector-python 9.7.0) — see CHANGELOG_ARCHIVE.md for the CVEs this closes. numpy 2.x and opencv-python 5.x are **major** version jumps from whatever 1.x/4.x was actually installed before (numpy 2.x has an ABI break and removed ~100 namespace members; see https://numpy.org/devdocs/numpy_2_0_migration_guide.html). This environment has no `pip` to install and actually run `app/` against the new pins, so **this is unverified** — run `pip install -r requirements.txt` and exercise `app/object_identification/obj_id.py` (the DNN/numpy/opencv code most likely to break) on a machine with pip before trusting this update.
- **Seeing object detection run on real photos, today, as a curiosity/POC detour — not a roadmap step.** `app/object_identification/obj_id.py` (YOLOv3 via OpenCV DNN) already exists in this prototype and would run against `resources/testpics`, but the actual model files were never fetched — `resources/darknet/` is gitignored (large binaries don't belong in git) and empty in every clone. To try it on a machine with `pip` (this environment doesn't have one — see the dependency-bump note above):
  1. `mkdir -p resources/darknet` (relative to this prototype's root).
  2. Fetch the three files into it: `yolov3.weights` from [github.com/AlexeyAB/darknet's `darknet_yolo_v3_optimal` release](https://github.com/AlexeyAB/darknet/releases/download/darknet_yolo_v3_optimal/yolov3.weights) (pjreddie.com, the original YOLOv3 author's own host, has been dead for years — this is the current live mirror, checked 2026-07-27), `yolov3.cfg` and `coco.names` from [pjreddie/darknet's `cfg/`](https://raw.githubusercontent.com/pjreddie/darknet/master/cfg/yolov3.cfg) and [`data/`](https://raw.githubusercontent.com/pjreddie/darknet/master/data/coco.names) directories respectively (small text files, that repo's own hosting is still fine for these).
  3. `pip install -r requirements.txt`, then run `obj_id.py` (or the `obj_id.ipynb` notebook) against `resources/testpics`.
  Explicitly **not** the architecture this project is committed to — VISION.md Pillar 2's actual plan is on-device, phone-side inference, not server-side OpenCV/YOLO, and there's no mobile app shell yet for that to run inside. This is purely "what does object detection output actually look like on a real photo," useful for building intuition before that real build phase starts.
