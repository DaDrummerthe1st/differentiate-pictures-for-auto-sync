# modules/

A standalone detector library — each file its own detector, growing over time. Deliberately no dependency on `detector/`, `app/`, or any other existing code in this repo, even where a detector here covers the same ground as an existing one. See [documentation/curation/DETECTORS.md](../documentation/curation/DETECTORS.md).

- `pictures.py` — the central metadata register (session 3 of [PICTURES_PIPELINE.md](../documentation/data-modeling/PICTURES_PIPELINE.md)). `GetListOfValidPictureFiles(folder_path, source=None, db_path=...)` walks a folder (recursively - a local directory today, an sshfs-mounted NAS share tomorrow), filters to real, decodable picture files, and registers them into a SQLite DB with two tables: `pictures` (one row per unique photo, keyed by MD5 - the same photo found again at a different path stays one picture) and `locations` (one row per place it's been found - path, an optional source label, and per-location filesystem stat metadata, since stat data is inherently per-location). Rescans are incremental: an unchanged path (same size/mtime) is skipped without re-hashing. `file_metadata` tries a true filesystem birth time via the `statx(2)` syscall (`STATX_BTIME`, via `ctypes` - Python's `os.stat()` never exposes this on Linux) and falls back to `birth_time_available=False` with `mtime`/`ctime` always present, never guessed. The DB file itself lives at `databases/pictures.db` (gitignored - it indexes real personal photo metadata).
- `quality.py` — blur, exposure, and saturation, each 0-100% (or -100 to +100 for exposure), plus `check_all()` bundling all three into one `QualityResult`. See [documentation/data-modeling/QUALITY_METRICS.md](../documentation/data-modeling/QUALITY_METRICS.md) for the column-shape reasoning.
- `objects.py` — object detection via NanoDet-Plus (Apache-2.0, COCO's 80 classes). `detect_objects()` returns a `DetectionResult` (all detections + image width/height, pixel-coordinate boxes); `has_object()` is a per-class convenience wrapper. Vendored model + license note: `models/LICENSES.md`.
- `test_main.py` — **not** a pytest test (no `test_*` functions, filename only matches the pytest pattern for a mid-session naming reason). A manual, local-only dev tool: `python3 -m modules.test_main` opens a tkinter window to pick a folder, then a second, scrollable, **paginated** (`IMAGES_PER_PAGE` at a time — rendering an entire large folder at once crashed the X server, fixed and confirmed 2026-09-04, `documentation/bugs/repo/fixed/2026-09-04-test-main-py-x-badalloc-rendering-100-photos-at-once-SOLVED.md`) window with one bordered entry per image — EXIF (camera/settings/GPS, reads it directly via PIL, no dependency on any other file in this repo), quality, and object detections, each its own labeled section, plus the photo with bounding boxes drawn on it. EXIF is read here only, not exposed as a `modules/` detector function — `app/gpsdata.py` (archived) already covers that ground and isn't imported from, per this directory's no-shared-code rule.
