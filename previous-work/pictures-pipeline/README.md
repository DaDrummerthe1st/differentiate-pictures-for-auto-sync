# modules/

A standalone detector library — each file its own detector, growing over time. Deliberately no dependency on `detector/`, `app/`, or any other existing code in this repo, even where a detector here covers the same ground as an existing one. See [documentation/curation/DETECTORS.md](../../documentation/curation/DETECTORS.md).

- `pictures.py` — the central metadata register (session 3 of [PICTURES_PIPELINE.md](../../documentation/data-modeling/PICTURES_PIPELINE.md)). `GetListOfValidPictureFiles(folder_path, source=None, db_path=...)` walks a folder (recursively - a local directory today, an sshfs-mounted NAS share tomorrow), filters to real, decodable picture files, and registers them into a SQLite DB with two tables: `pictures` (one row per unique photo, keyed by MD5 - the same photo found again at a different path stays one picture) and `locations` (one row per place it's been found - path, an optional source label, and per-location filesystem stat metadata, since stat data is inherently per-location). Rescans are incremental: an unchanged path (same size/mtime) is skipped without re-hashing. `file_metadata` tries a true filesystem birth time via the `statx(2)` syscall (`STATX_BTIME`, via `ctypes` - Python's `os.stat()` never exposes this on Linux) and falls back to `birth_time_available=False` with `mtime`/`ctime` always present, never guessed. The DB file itself lives at `databases/app.db` (gitignored - it indexes real personal photo metadata; named `app.db` rather than `pictures.db` since `contacts/db.py` shares the same file). `get_location(location_id, db_path=...)` and `list_locations_under(folder_path, db_path=...)` (added for `web/`, 2026-09-05) look up one registered location, or every location whose path is inside a given folder, sorted by path.
- `quality.py` — blur, exposure, and saturation, each 0-100% (or -100 to +100 for exposure), plus `check_all()` bundling all three into one `QualityResult`. See [documentation/data-modeling/QUALITY_METRICS.md](../../documentation/data-modeling/QUALITY_METRICS.md) for the column-shape reasoning.
- `objects.py` — object detection via NanoDet-Plus (Apache-2.0, COCO's 80 classes). `detect_objects()` returns a `DetectionResult` (all detections + image width/height, pixel-coordinate boxes); `has_object()` is a per-class convenience wrapper. Vendored model + license note: `models/LICENSES.md`.
- `findings.py` — EXIF reading (`exif_lines()`) and detection-annotation (`annotate()`, boxes+labels drawn on a resized copy of the photo, including the EXIF-rotation-matching assertion described below), extracted 2026-09-05 so both `test_main.py` and `web/` display a photo's findings identically instead of duplicating that logic (and its EXIF-rotation gotcha) a second time.
- `test_main.py` — **not** a pytest test (no `test_*` functions, filename only matches the pytest pattern for a mid-session naming reason). A manual, local-only dev tool: `python3 -m modules.test_main` opens a tkinter window to pick a folder, then a second, scrollable, **paginated** (`IMAGES_PER_PAGE` at a time — rendering an entire large folder at once crashed the X server, fixed and confirmed 2026-09-04, `documentation/bugs/repo/fixed/2026-09-04-test-main-py-x-badalloc-rendering-100-photos-at-once-SOLVED.md`) window with one bordered entry per image — EXIF (camera/settings/GPS, via `findings.exif_lines()`), quality, and object detections, each its own labeled section, plus the photo with bounding boxes drawn on it (`findings.annotate()`).
- `web/` — the same viewing experience as `test_main.py`, in a browser instead of tkinter. `python3 -m modules.web.server`, then open `http://127.0.0.1:8766/`. A local-only HTTP server (stdlib only, no framework), fully server-rendered, no client-side JS: `GET /` (a folder-path form) → `POST /scan` (registers the folder into `pictures.py`'s SQLite register, redirects to) → `GET /pictures?folder=&page=` (a paginated thumbnail grid, `IMAGES_PER_PAGE` at a time — same X-server-pixmap rationale as `test_main.py`'s pagination, though a browser's own image decoding is the constraint here rather than X pixmaps; a small badge overlay, plain HTML/CSS, marks photos `objects.detect_objects()` found something in) → clicking a thumbnail opens `GET /picture/<location_id>` (EXIF/quality/objects findings plus the full-size annotated image, same content as `test_main.py`'s per-entry box). Image bytes (`GET /image/<location_id>?variant=thumb|full`) are generated server-side per request - `web/imaging.py`'s `thumbnail()` for the grid, `findings.annotate()` for the full-size boxed view - and streamed back as JPEG. Unlike `test_main.py` (which walks a folder directly), this reads from the existing `pictures.py` register rather than re-walking on every page view. Nothing goes past 127.0.0.1.
